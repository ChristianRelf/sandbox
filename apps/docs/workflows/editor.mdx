The workflow editor stores a typed graph: nodes hold configuration and input bindings, while edges define control flow. Visual proximity alone never passes data or changes execution order.

## Add and connect nodes

Open the node picker from the toolbar, canvas, or a node's add control. Drag a control handle to a valid target. A Condition node exposes separate `true` and `false` source handles. Trigger nodes cannot be connection targets, and self or duplicate connections are rejected.

## Configure the selected node

The right inspector is generated from the real node type. It exposes configuration, typed data bindings, locator testing, connection/profile selectors, and risk information only when the node implements those controls. The footer offers node testing and deletion; configured-node deletion can require confirmation according to Settings.

## Validate before execution

Validation reports the exact node, edge, or field path when possible. Select a validation row to focus the affected node. Errors block execution; warnings identify reviewable behavior without pretending a workflow is invalid.

## Save and revisions

Content-changing saves create immutable revision records. Restore creates a new head revision rather than editing history. Cloud workspace drafts add approval and publication on top of the same revision identity.

## Pointer-free editing

Select **Accessible editor** for named controls that add, move, connect, inspect, and remove graph elements without dragging. See [Accessible editor](/workflows/accessible-editor).
