The current engine workflow schema version is **6**. Imports reject schema 0 and versions newer than the running build. Versions 1 through 5 are deterministically normalised to version 6 before storage without rewriting unrelated node content. Published revisions remain immutable.

```ts title="Workflow"
interface Workflow {
  id: string;
  schemaVersion: number;
  owner?: { ownerType: "personal" | "workspace"; ownerId: string };
  name: string;
  description: string;
  enabled: boolean;
  triggerNodeId: string;
  nodes: WorkflowNode[];
  edges: WorkflowEdge[];
  settings: WorkflowSettings;
  createdAt: string;
  updatedAt: string;
}
```

```ts title="Node and edge"
interface WorkflowNode {
  id: string;
  type: string;
  version: number;
  name: string;
  position: { x: number; y: number };
  configuration: Record<string, unknown>;
  disabled: boolean;
  inputBindings?: Record<string, InputBinding>;
  plugin?: PluginNodePin;
}

interface WorkflowEdge {
  id: string;
  sourceNodeId: string;
  sourceHandle: string;
  targetNodeId: string;
  targetHandle: string;
  kind?: "control";
  sourcePort?: string;
  targetPort?: string;
}
```

```ts title="Settings"
interface WorkflowSettings {
  defaultNodeTimeoutMs: number;
  maxConcurrentNodes: number;
  permissions: PermissionSummary;
  expressionLanguageVersion: number;
  collectionLimits: CollectionLimits;
}
```

Version 6 adds stable collection limits and internal item evidence. Existing node output remains JSON-compatible; nodes are not forced to expose an envelope in user mappings.

```ts title="Workflow item evidence"
interface WorkflowItem {
  itemId: string;
  originItemId?: string;
  parentItemId?: string;
  data: unknown;
  binary?: Record<string, BinaryReference>;
  trustedPaths?: Record<string, string>;
  sourceNodeId?: string;
  sourceItemIndex?: number;
  originalPosition?: number;
  currentPosition?: number;
  branch?: string;
  branchHistory?: string[];
  loopIteration?: number;
  executionAttempt: number;
  status: string;
  correlations?: Record<string, string>;
}
```

Switch branch IDs and Merge input IDs are stored in node configuration. Edges refer to those stable IDs through `sourceHandle` and `targetPort`; display-name changes and case reordering do not rewrite the edge identity. Control edges still decide eligibility, while input bindings still decide field values.

Use the editor, import/export envelope, or typed API rather than editing a stored database row. Generated node pages show the exact version 1 configuration defaults for all built-in node types.

## AI and code-capable nodes

The current built-in IDs are `ai_prompt`, `code`, and `web_builder`. Their exact default configurations and ports are generated in the [AI](/nodes/ai-prompt), [Code](/nodes/code), and [Web Builder](/nodes/web-builder) references.

AI connections are stored as IDs in `configuration.connectionId`; credentials never enter the schema. Code source is stored in `configuration.sourceCode`. A Web Builder receives source through ordinary `node_output` bindings, with each binding pointing to the upstream Code node's `code` output. Python and JavaScript `executionMode: "run"` also require revision-bound command-execution permission.
