**Node type:** `fill_field` · **Version:** `1` · **Category:** Browser

Enter static or protected data. This node is not marked with the catalogue's generic side-effect flag. That classification is not a guarantee that every configured operation is read-only; review the concrete action and its destination.

## When to use this node

- Enter mapped text into a recorded form control.
- Resolve a protected value at runtime and keep it redacted from evidence.

## Example: Fill a protected password

Record the password field, map a protected variable to value, clear old content, and mark the input sensitive.


```json title="Example settings"
{
  "locator": {
    "primary": {
      "kind": "label",
      "value": "Password",
      "name": "Password"
    },
    "alternatives": []
  },
  "value": "",
  "clearExisting": true,
  "inputDelayMs": 0,
  "sensitive": true,
  "timeoutMs": 30000
}
```

This shows the important settings, not a complete exported node. The locator is shortened for readability; use the recorder to create the complete structured locator bundle.


1. Record the field by label or accessible role.
2. Map the protected variable instead of storing literal secret text.
3. Test that logs show redaction and that the page accepted the value.


## Configuration

| Field | Type | Default | What it controls |
| --- | --- | --- | --- |
| `locator` | locator | `null` | Recorded locator bundle. sndbox prefers accessible role/name data and retains fallbacks. |
| `value` | string | `""` | Literal value, protected reference, or mapped output. |
| `clearExisting` | boolean | `true` | Clear the field before entering the value. |
| `inputDelayMs` | number | `0` | Delay between entered characters, from 0 to 2000 milliseconds. |
| `sensitive` | boolean | `false` | Treat the mapped value as protected and redact it from execution data. |
| `timeoutMs` | number | `30000` | Maximum time for this operation in milliseconds. |

<Note>Enable `sensitive` for protected mappings so entered values are redacted from logs and execution data.</Note>

## Execution behavior

- clearExisting replaces current content; otherwise input is appended using the browser's field behavior.
- sensitive marks the resolved value for redaction but does not change the destination website's handling of it.
- The editor catalogue declares `result` (any) for mapping. The execution inspector can contain additional evidence fields; inspect a real result before selecting nested paths from object or any outputs.

## Common issues

- A sensitive field with no protected mapping is intentionally incomplete.
- Framework-controlled inputs can reformat values; verify the resulting page state instead of assuming keystrokes were accepted.
