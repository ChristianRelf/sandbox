**Node type:** `gmail_send_email` · **Version:** `1` · **Category:** Communication

Send only after explicit workflow approval. sndbox classifies this node as side-effecting, so tests or automatic runs can require additional confirmation and permission review.

## When to use this node

- Send an approved transactional or notification email from a connected Gmail account.
- Continue an existing thread after recipient logic has been reviewed.

## Example: Send an approved report

Send a mapped summary and approved attachment to a fixed recipient.


```json title="Example settings"
{
  "credentialId": "gmail-reports",
  "to": "ops@example.com",
  "cc": "",
  "bcc": "",
  "subject": "Daily report",
  "body": "{{nodes.ai.output.response}}",
  "htmlBody": "",
  "replyToMessage": "",
  "attachments": [
    "{{nodes.write.output.path}}"
  ]
}
```

This shows the important settings, not a complete exported node. Connection and profile IDs are illustrative; select the real resource in the inspector. Local paths must be selected, mapped from a trusted path, or covered by the runner's approved boundary.


1. Keep recipient logic narrow and visible.
2. Put a Manual Approval node before Send Email for run-time review when appropriate.
3. Publish and approve the exact workflow revision before automatic use.


## Configuration

| Field | Type | Default | What it controls |
| --- | --- | --- | --- |
| `credentialId` | string | `""` | Reference to a connection stored in the operating-system credential vault. |
| `to` | string | `""` | Comma-separated or mapped recipient value. |
| `cc` | string | `""` | Optional CC recipients. |
| `bcc` | string | `""` | Optional BCC recipients. |
| `subject` | string | `""` | Email subject or approval subject. |
| `body` | string | `""` | JSON request body for POST, PUT, and PATCH requests. |
| `htmlBody` | string | `""` | Optional HTML email body. |
| `replyToMessage` | string | `""` | Optional Gmail message ID to reply to. |
| `attachments` | array | `[]` | Approved attachment paths. |

<Note>Automatic sending requires approval for the selected connection and recipient logic. A material change revokes that approval.</Note>

## Execution behavior

- The node performs an external communication side effect and requires both general communication permission and revision-bound send approval.
- Attachments must resolve to approved paths.
- The editor catalogue declares `result` (any) for mapping. The execution inspector can contain additional evidence fields; inspect a real result before selecting nested paths from object or any outputs.

## Common issues

- Changing recipient logic or other material workflow behavior revokes approval.
- Retries can duplicate mail unless the surrounding workflow has a deduplication strategy.
