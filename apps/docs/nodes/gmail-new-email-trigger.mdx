**Node type:** `gmail_new_email_trigger` · **Version:** `1` · **Category:** Triggers

Poll Gmail safely for matching messages. This node is not marked with the catalogue's generic side-effect flag. That classification is not a guarantee that every configured operation is read-only; review the concrete action and its destination.

## When to use this node

- Start triage, drafting, or notification flows from matching Gmail messages.
- Filter at the trigger when only a sender, recipient, subject fragment, label, or attachment state is relevant.

## Example: Draft replies to support mail

Poll a connected support inbox every five minutes for messages whose subject contains Support.


```json title="Example settings"
{
  "credentialId": "gmail-support",
  "pollIntervalMinutes": 5,
  "sender": "",
  "recipient": "support@example.com",
  "subjectContains": "Support",
  "hasAttachment": false,
  "label": "",
  "includeHtmlBody": false,
  "markAsProcessed": "deduplicate"
}
```

This shows the important settings, not a complete exported node. Connection and profile IDs are illustrative; select the real resource in the inspector.


1. Select the Gmail connection and add the narrowest useful filters.
2. Map fields from the email output into analysis or draft nodes.
3. Prefer Create Gmail Draft until the recipient logic has been reviewed.


## Configuration

| Field | Type | Default | What it controls |
| --- | --- | --- | --- |
| `credentialId` | string | `""` | Reference to a connection stored in the operating-system credential vault. |
| `pollIntervalMinutes` | number | `5` | How often sndbox checks Gmail for matching messages. |
| `sender` | string | `""` | Optional sender filter. |
| `recipient` | string | `""` | Optional recipient filter. |
| `subjectContains` | string | `""` | Optional text that must occur in the message subject. |
| `hasAttachment` | boolean | `false` | Require at least one attachment. |
| `label` | string | `""` | Optional Gmail label filter. |
| `includeHtmlBody` | boolean | `false` | Include HTML in addition to the plain-text body. |
| `markAsProcessed` | string | `"deduplicate"` | Persist message IDs per workflow so a message cannot trigger repeatedly. Values: `deduplicate`. |

<Note>Message IDs are persisted per workflow to prevent the same email from starting repeated runs.</Note>

## Execution behavior

- sndbox persists observed message IDs per workflow so the same message does not repeatedly trigger it.
- Plain text is included by default; enabling HTML increases the amount and sensitivity of data stored in execution evidence.
- The editor catalogue declares `email` (object) for mapping. The execution inspector can contain additional evidence fields; inspect a real result before selecting nested paths from object or any outputs.

## Common issues

- A poll interval is not an exact delivery SLA; the next poll must run and the event must enter the queue.
- If no messages match, test each filter independently and confirm the connection can still access the mailbox.
