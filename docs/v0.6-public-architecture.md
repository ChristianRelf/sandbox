# Sandbox v0.6 public architecture

Status: implementation baseline; production publication blocked by missing v0.5 services and deployment configuration.

## Domain and routing model

| Domain | Workspace | Responsibility | Runtime |
| --- | --- | --- | --- |
| `sandbox.com` | `apps/marketing` | Marketing, product education, solutions, pricing gate, public marketplace, templates, downloads, changelog, security, enterprise, support and legal review routes | Independent Next.js application, port 3100 locally |
| `app.sandbox.com` | `apps/web` | Authentication entry, account, marketplace purchases, releases, licences, billing, usage, organisations, security and support readiness | Independent Next.js application; existing marketplace API integration retained |
| `docs.sandbox.com` | `apps/docs` | Version-labelled product manual, code examples, troubleshooting and client-side documentation search | Independent statically generated Next.js application, port 3200 locally |

The desktop Tauri application remains the only workflow editor. None of the public applications imports the desktop editor or its browser runtime.

## Shared packages

- `@sandbox/brand` owns the name, core message, canonical domains and web colour tokens.
- `@sandbox/ui` owns small cross-surface action and status primitives without importing dashboard dependencies.
- `@sandbox/content` owns reviewed product, use-case, release, legal-route and transactional-email records.
- `@sandbox/api-client` owns typed public marketplace reads and is suitable for authenticated extensions.

The applications deploy independently and do not share Next.js layouts. This keeps marketing JavaScript isolated from the authenticated portal.

## Cross-domain transitions

- Marketing pricing and downloads lead to the account or desktop download journey only when an entitlement-backed action exists.
- Template actions use `sandbox://templates/import?template=…&enabled=false`, then fall back to `/downloads`.
- Documentation links to account actions explicitly use `app.sandbox.com`; ordinary reading remains public.
- Account releases link back to the public changelog.
- Authentication accepts only a relative, non-protocol `returnTo` path before storing it in OIDC state.

## Deployment and rollback

No `.openai/hosting.json`, Vercel project, Cloudflare configuration or production domain credentials exist in this checkout. Production deployment was not attempted.

Build commands:

```powershell
npm.cmd install
npm.cmd run marketing:build
npm.cmd run web:build
npm.cmd run docs:build
```

Expected production configuration:

```text
apps/marketing: NEXT_PUBLIC_MARKETING_URL, CONTROL_PLANE_URL, ENQUIRY_ROUTER_URL
apps/web: CONTROL_PLANE_URL, OIDC_AUTHORIZE_URL, OIDC_CLIENT_ID, OIDC_REDIRECT_URI
apps/docs: NEXT_PUBLIC_DOCS_URL
```

Deploy each workspace as an independent immutable build. Roll back by redeploying the preceding successful artifact for that one surface; never roll back the desktop or control plane merely to revert marketing content.
